# make-knowledge-cards

把一篇文章转换成 5～8 张知识卡片的 Skill。每张卡片只讲一个知识点，内容严格来自原文。

## 1. 解决什么问题

读长文的常见困境不是「没读」，而是读完留不下可复用的东西：

- 要点散落在几千字里，第二次要用时只能重读。
- 手工做摘要容易写成「这段讲了什么」，无法脱离原文独立复习。
- 通用摘要工具倾向于压缩和润色，会顺手补上原文没有的因果、建议和数据。
- 内容本身水分大时，摘要工具仍会输出固定条数的要点，形成看似完整的无效卡片。

本 Skill 针对这四点给出固定流程：抽取知识点、去重、一张卡只承载一个知识点、数量服从原文信息量。信息不足时它宁可少出或不出卡片，也不凑数。

## 2. 主要功能

| 功能 | 实际行为 |
| --- | --- |
| 输入解析 | 支持粘贴正文、本地 `.md`、本地 `.txt`；读取时剥离导航、作者简介、广告、评论区等非正文内容 |
| 卡片结构 | 每张卡片固定四段：标题、核心知识、简明解释、例子或自测问题 |
| 一卡一知识点 | 两个可独立提问的结论会被拆成两张卡；上位与下位概念不重复成卡 |
| 去重 | 同一结论的不同措辞合并为一张；并列枚举合并为一张「清单卡」，不逐项凑数 |
| 数量自适应 | 5～8 张为常态；有效知识点 3～4 个时出 3～4 张并注明；不足 3 个时不出卡片 |
| 事实与主张分离 | 观点类文章的卡片以 `事实：` 或 `作者主张：` 开头，并注明原文是否给出论据 |
| 语言跟随原文 | 英文文章输出英文卡片，中文文章输出中文卡片；用户指定语言时以用户为准 |
| 输出位置 | 默认在对话中返回 Markdown，不写文件；用户要求时才保存为 `.md` |

明确不做的部分：不抓取网页、不解析 PDF/docx/图片/音频、不导出 Anki（`.apkg`）、不提供图形界面。

## 3. 安装方法

前置条件：一个能加载 Skill 目录的运行环境（WorkBuddy 等）。本 Skill 不含任何脚本，没有 Python / Node 依赖。

**用户级安装**（对所有项目生效）：

```bash
mkdir -p ~/.workbuddy/skills
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/
```

```powershell
New-Item -ItemType Directory -Force "$HOME\.workbuddy\skills" | Out-Null
Copy-Item -Recurse "skills\make-knowledge-cards" "$HOME\.workbuddy\skills\"
```

**项目级安装**（仅对当前项目生效）：

```bash
mkdir -p .workbuddy/skills
cp -r skills/make-knowledge-cards .workbuddy/skills/
```

安装完成后，目标目录应至少包含 `SKILL.md`；缺少该文件时 Skill 不会被识别。

## 4. 使用方法

安装后直接用自然语言发起请求即可，无需记命令：

```text
把这篇文章做成知识卡片：<粘贴正文>
把 docs/notes.md 转成知识卡片
这篇文章读完记不住，提炼几张卡片
把这篇英文文章做成知识卡片，用中文输出
```

**输入方式**：正文直接粘贴，或给出 `.md` / `.txt` 的本地路径（Skill 会自行读取）。链接、PDF、图片、docx 会被拒绝，并提示改为粘贴正文或另存为 `.md` / `.txt`。

**输出位置**：默认只在对话中输出。需要文件时说一句「存成 md 文件」。

**数量与边界**：

| 原文有效知识点 | 输出 |
| --- | --- |
| ≥ 5 个 | 5～8 张，按信息密度取舍，总数不超过 8 张 |
| 3～4 个 | 如实输出 3～4 张，开头注明「未凑足 5 张」 |
| < 3 个 | 不出卡片，改为说明信息缺口、列出可提取要点、建议补充材料 |

**触发方式**：`agents/openai.yaml` 中 `allow_implicit_invocation` 为 `true`，因此粘贴文章说「做成卡片」「提炼要点」也会命中；若希望只在显式调用时启用，把该值改为 `false`。

## 5. 输入输出示例

### 示例一：信息量充足

输入（`tests/inputs/05-edge-three-points.md` 节选）：

> 实际上弗朗西斯科·西里洛当年用的是厨房里的番茄形计时器，25 分钟就是那个计时器的固定刻度。这个数字没有生理学依据，它对多数人好用的原因是短到你没有理由拖延，并不是因为它匹配某个专注力周期。

输出（该文件实际输出共 3 张，此处取第 1 张）：

```markdown
# 知识卡片：番茄工作法的三个细节

原文约 600 字，提取 3 张卡片。

> 原文有效知识点约 3 个，未凑足 5 张。

---

## 卡片 1｜25 分钟来自计时器刻度而非研究

**核心知识：** 25 分钟这一数字源自番茄形厨房计时器的固定刻度，没有生理学依据。

**简明解释：** 西里洛当年使用的就是厨房计时器的固定时长，该数字并非来自注意力研究。原文特别指出，它之所以被广泛引用，是因为好用，而不是因为有实验支撑。

**自测：** 为什么不能把 25 分钟当作有科学依据的专注时长？

> 参考答案要点：它来自厨房计时器的固定刻度，原文明确说明其背后没有生理学依据。
```

### 示例二：观点类文章

输入（`tests/inputs/03-opinion-saas-seat-pricing.md` 节选）：

> 我的判断是，未来的主流会是混合计价：一个覆盖基础能力的平台费，加一层按实际用量的计量。

输出（该文件共 7 张，此处取第 6 张，注意前缀标注）：

```markdown
## 卡片 6｜混合计价兼顾可预期与价值捕获

**核心知识：** 作者主张：平台费加用量层的混合计价是未来主流形态。

**简明解释：** 平台费覆盖基础能力并给出预算锚点，解决收入可预期的问题；用量层捕获实际使用带来的价值。作者认为平台费提供的锚点是混合计价比纯用量计价可行的关键。

**自测：** 混合计价中平台费承担什么功能？

> 参考答案要点：覆盖基础能力并为客户预算提供锚点，使成本可预期。
```

### 示例三：信息不足

输入 `tests/inputs/04-sparse-repetitive.md`（约 270 字，通篇重复「喝水非常重要」）后，不输出卡片，改为：

```markdown
# 知识卡片：关于喝水，你需要知道的

原文约 270 字。**无法生成卡片：原文有效知识点不足 3 个。**

## 为什么不出卡片
（说明哪些内容属重复重述、哪些只有结论没有依据、哪些是号召性语句）

## 原文中可提取的要点
（列出 1～2 条，标明不足以成卡）

## 建议补充的材料
（说明需要补齐哪类信息才能得到可用卡片）
```

完整输出见 `tests/outputs/` 下同名文件。

## 质量规则

写进 `SKILL.md` 并在每次输出前逐条自检的硬约束：

1. 每条核心知识都能在原文找到对应句子，不编造因果、数字、建议。
2. 任意两张卡片不得在讲同一件事；出现即合并。
3. 不为凑数拆句、换措辞重述或补充背景。
4. 作者判断不写成事实，观点类文章必须标注前缀。
5. 结尾的总结段、号召段不单独成卡。

## 测试

用六篇不同类型文本验证，输出见 `tests/outputs/`：

| 用例 | 类型 | 实际字数 | 结果 |
| --- | --- | --- | --- |
| 01 城市热岛 | 科普说明文，机制密集 | 约 960 字 | 7 张，现象卡与机制卡分离 |
| 02 Git rebase | 操作教程，`.txt` 输入 | 约 1100 字 | 8 张，动作表合并为清单卡 |
| 03 席位定价 | 观点评论，事实与主张混杂 | 约 820 字 | 7 张，逐张标注事实/作者主张 |
| 04 喝水 | 重复空话，仅 1 条事实 | 约 270 字 | 不出卡片，说明信息缺口 |
| 05 番茄工作法 | 仅 3 个知识点 | 约 600 字 | 3 张，开头注明未凑足 |
| 06 Bread staling | 英文说明文 | 约 300 words | 6 张，保持英文输出 |

测试驱动了七处修订：结尾总结段不成卡、并列枚举合并为清单卡、现象与机制不重复写因果、观点前缀标注、操作类文章优先引用原文命令作例子、卡片语言随原文、字数改为工具统计而非目测估算。

## 元数据

`agents/openai.yaml` 供兼容 Skill 目录的运行器读取：

```yaml
interface:
  display_name: "知识卡片生成"
  short_description: "把文章转换成 5-8 张一卡一知识点的学习卡片"
  default_prompt: "使用 $make-knowledge-cards 把这篇文章做成知识卡片。"
policy:
  allow_implicit_invocation: true
```

## 已知限制

- 卡片质量取决于原文信息密度；原文本身空泛时，本 Skill 的做法是少出卡而不是补内容。
- 字数统计对粘贴文本为量级估算；文件输入按工具统计结果，显示时保留到百位。
- 未做去重跨文章合并，一次只处理一篇。
